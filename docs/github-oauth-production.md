# GitHub OAuth Production Setup & Security Specification

**Document Version:** 1.0.0  
**Integration Type:** GitHub OAuth 2.0 Web Application  
**Standard Authorization Endpoint:** `https://github.com/login/oauth/authorize`  
**Standard Token Endpoint:** `https://github.com/login/oauth/access_token`  
**Derived Callback Path:** `/api/integrations/github/callback`

---

## 1. Production GitHub OAuth Application Settings

In your GitHub Account or Organization (**Settings** -> **Developer settings** -> **OAuth Apps** -> **New OAuth App**):

| Setting | Production Configuration | Development Configuration |
| :--- | :--- | :--- |
| **Application name** | `DeployX` | `DeployX (Local Dev)` |
| **Homepage URL** | `https://deployx.yourdomain.com` | `http://localhost:3000` |
| **Application description** | `Developer deployment and cloud hosting orchestration platform` | `Local developer environment` |
| **Authorization callback URL** | `https://deployx.yourdomain.com/api/integrations/github/callback` | `http://localhost:3000/api/integrations/github/callback` |
| **Enable Device Flow** | Disabled | Disabled |

> [!IMPORTANT]
> GitHub does not allow wildcard redirect URLs. The authorization callback URL entered in GitHub Developer Settings must **character-for-character match** the canonical callback URL generated by DeployX (`${NEXT_PUBLIC_APP_URL}/api/integrations/github/callback`).

## 2. OAuth Credentials & Secret Management

1. **Client ID (`GITHUB_CLIENT_ID`):**
   - Public identifier assigned by GitHub (e.g., `Ov23...` or `Iv1...`).
   - Stored in server environment variables.
2. **Client Secret (`GITHUB_CLIENT_SECRET`):**
   - 40-character hexadecimal secret.
   - **Never** exposed to the client browser or included in frontend bundles.
   - Stored exclusively in the hosting platform's encrypted environment variables.
3. **Secret Rotation Procedure:**
   - If rotating secrets, generate a new client secret in GitHub Developer settings.
   - Update `GITHUB_CLIENT_SECRET` in your hosting dashboard (e.g. Vercel/Railway).
   - Once verified, delete the old secret in GitHub.

## 3. Scopes & Least-Privilege Access

DeployX requests the minimum scopes required for repository deployment:
- `read:user`: To display the connected GitHub username, avatar, and account status in account settings.
- `repo`: To discover repositories and branches, clone repository code for deployment packaging, and configure auto-deploy webhooks on the repository.

---

## 4. State Verification & Token Encryption at Rest

1. **Anti-CSRF Nonce (`oauth_state`):**
   - Every authorization initiation generates an encrypted state cookie (`oauth_state`) bound to the authenticated user ID and a cryptographic nonce.
   - State expiration: 10 minutes (`OAUTH_STATE_MAX_AGE`).
   - State replay attacks or cross-tenant callbacks are strictly rejected.
2. **AES-256-GCM Token Encryption:**
   - Once acquired, GitHub personal access tokens are encrypted with authenticated AES-256-GCM (`lib/auth/encryption.ts`) before insertion into MongoDB Atlas.
   - Plaintext tokens are never stored in the database.
